# extensify
Addon "store" which isn't a store

Enables you to have lots of fun "additions" to your browser.

These are simple little tweaks, not things to make entire extensions about - so you can include them here!

## Load the extension

This workspace is the extension directory. There is no build step or web server: in Chrome or Edge, open the extensions page, enable Developer mode, choose **Load unpacked**, and select this repository folder (the folder containing `manifest.json`). Keep the whole folder together when loading it. The manifest grants connection access to `*.supabase.co` for the configured catalog and auth; a custom Supabase domain must also be added under `host_permissions` in `manifest.json`.

The popup and local addon workflows work without an account. The extension ships with one maintainer-configured Supabase project in root `supabase.json` (`projectRef`, `url`, and public `anonKey`/publishable key). End users do not edit this file. Never put a service-role key in the extension. Creator accounts sign in with email and password, so the extension does not need an auth redirect URL.

One-time maintainer setup: apply `supabase/migrations/202610110001_extensify_schema.sql` in the Supabase SQL editor, create the creator account in Supabase Auth, then run the migration’s final `extensify_admins` insert with that Auth user UUID. This is project setup before release, not a step for extension users. Keep Row Level Security enabled. After changing `supabase.json`, reload the extension.

To create a package, open **Editor**, choose an existing project or create a new one, edit `config.json` and other files as readable text, then use **Save ZIP** or **Save draft**. Put the full Markdown description in `addon-description.md`. Set `logo` in `config.json` to a Phosphor icon name plus hex color, or an included SVG path. Right-click files to rename or delete them. **Load ZIP** imports and validates a package. **Install locally** installs or refreshes the local copy and opens its addon detail page. Signed-in creator accounts get a **Publish** action for the shared catalog. Addons run through Chromium’s **Allow User Scripts** permission, which you must enable on the extension details page before enabling an addon. Extension changes are applied from this folder directly; use **Reload** on the extensions page after editing extension files.

If the extension is already connected to Supabase, rerun `supabase/migrations/202610110001_extensify_schema.sql` after updating the extension. The migration is safe to run again and adds the `logo` column needed by the current catalog. This is maintainer-side schema setup, not an action required from extension users.

Run the included logic checks with `node --test` (Node.js 20 or newer). These cover package validation, storage/install lifecycle, data import/export, Supabase row mapping, and ZIP round trips.
